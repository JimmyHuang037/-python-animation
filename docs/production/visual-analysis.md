# 视频视觉分析：为制作提供可执行依据

状态：方法与首轮静态观察已整理；连续片段尚未获取。

## 要回答的问题

不是只写“高级、好看”，而是回答：学生先看哪里，代码与图示怎样对应，什么时候改变画面，口播结束后留了多少阅读时间，哪些界面元素妨碍理解。

## 工作方法

1. 选择有代表性的概念、执行图解、真实代码操作片段。保存来源URL、分集、原始时间区间和本地文件哈希。
2. 用ffprobe记录真实媒体参数；粗抽帧定位场景变化，再对关键动作加密取样。自动切镜只做辅助，逐项出现的列表元素可能不是一次切镜。
3. 联系表带时间戳用于整体结构，原尺寸单帧用于代码字号、对齐、留白和颜色观察；裁去播放器UI后仍保留原坐标信息。
4. 对照字幕或口播标出“说到什么时发生什么”。相邻静帧只能说明状态差异，缺少中间过程时不能判定缓动曲线或精确动作时长。
5. 分离“观察”“推断”“本项目改法”；所有动画软件归属另按作者证据确认。

## 每段分析表

| 字段 | 记录内容 |
|---|---|
| reference / range | URL、分集、起止秒 |
| shot / frame | 镜头ID、帧时间与图片路径 |
| learning_action | 本镜头希望学生理解或完成的动作 |
| composition | 代码／图示／输出／字幕区域和相对比例 |
| hierarchy | 首要注意点、次要说明、背景信息 |
| typography | 字号估计、字体类别、行距；无法识别具体字体时不猜名 |
| motion | 元素出现顺序、方向、停顿；标注证据分辨率 |
| audio_alignment | 口播触发词与画面事件的对应 |
| adaptation | 用在本课哪题、哪些装饰去掉、怎样检测理解 |

## 本项目候选视觉原则

- 先试16:9 1080p；讲解代码尽量保持短而完整，复杂程序按任务拆镜头。
- 相对固定的代码、状态、输出和字幕区域，让学生知道下一步去哪里找信息。
- 执行焦点与语法配色区分；判断结果同时用文字/位置表达，不只靠红绿。
- 列表追加展示新元素位置；删除展示被删除位置与结果；字典强调键值对应。
- 题目首次出现不提前泄露答案；讲评再显示状态变化和完整代码。
- 真实IDE片段裁掉不相关侧栏，保留输入、运行与错误现场；代码字号应与动画段接近。

这些是待样片验证的建议，不是作者的精确设计参数。不要把画面中B站播放器的进度曲线、水印或操作控件当作课程组件。

## 输出

带时间戳的关键帧、镜头分析表、候选视觉参数、可复用动画动作清单，以及迁移到“列表筛选”样片的分镜。不能用网页抓取成功冒充完成了这项视觉分析。
