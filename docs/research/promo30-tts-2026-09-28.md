## 与当前工程衔接

当前 src/project.ts 只配置 scenes，README 的 FFmpeg 命令在最后加入 music-original.wav；配音应在最终混音阶段接入。画面时序合适时可直接复用现有 MP4 的视频流，不必重渲 900 帧。

1. 按现有分镜分段写口播，保留各句 WAV 和实际时长。
2. 每句先试音，再测时长。优先改文案，其次微调语速；不能把超时口播直接截到 30 秒。
3. 按对应起点拼入一条 30 秒 narration.wav；留空处补静音。5–6 秒只有一秒，建议留给音乐重音，不硬塞“一站式解决”五个字。
4. 口播时压低原创音乐，混音后检查响度、峰值和可懂度。需要自动避让可用 FFmpeg sidechaincompress，再与人声 amix。
5. 使用 FFmpeg 映射现有视频流与新混音，视频可用 -c:v copy，音频 AAC，另存配音版。仅在需要改变画面节奏时重渲 Motion Canvas。
6. 字幕按每段实际声音时长及起点平移；TTS 返回的字幕不能直接当动画事件时间轴。整片连续听看，检查 Python 发音、句尾截断和重点动作同步。

建议口播草案（不是已生成或保证能放入的最终时长）：

| 时间 | 口播 |
| --- | --- |
| 0–5 秒 | Python 难学，听不懂，也不想动手？ |
| 5–6 秒 | 留白，音乐重音 |
| 6–10 秒 | 从学分要求出发，明确期末目标。 |
| 10–19 秒 | 用动画看懂每一步。看，九十加入末尾，列表就多了一个元素。 |
| 19–25 秒 | 结合上海高校考情，熟悉判断、填空和编程。 |
| 25–30 秒 | 让学习更清楚，向期末目标迈进。 |
