# Gitee 任务与 AI 交接模板

日期：2026-10-01。状态：已与共用规则对齐的可复制模板，尚未发布远端任务。适用于项目负责人 / DevOps、Canvas A、Canvas B、IDE 制作者及各自 AI，四人各用本机 WSL + Docker。

按根 [AGENTS](../../AGENTS.md)、小节 README和本组 req/status执行；全课范围见[课程 README](../../course/README.md)，需要协作方法时查[四人工作流](team-workflow-2026-10-01.md)。项目负责人统筹与合并；任务执行者是具体任务的一名成员。完整正文可放 Issue、仓库任务文件或用户明确授权的聊天，不要求已有线上派工系统。每课细纲暂不修改，实际用到再处理。

## Issue 正文

```markdown
标题：[Canvas / IDE / DevOps / 集成 / 文档] 一个具体可验收的结果

任务类型：
任务执行者：一位真人（项目负责人也可承担具体任务）
审查人：另一位成员
项目负责人：统筹需求、集成与合并
优先级 / 目标日期：按任务安排

目标：学生或制作者最终能看到/完成什么？
当前问题：什么具体操作触发了什么错误？

输入：
- 需求条目或已有编号、正文版本/日期（无编号可引用条目，不造已实施编号）：
- 制作线、共同小节README、本组requirements.md / status.md路径（非制作任务可标不适用）：
- Git基准提交：
- 当前任务完整正文和资料取得方法：
- Canvas/IDE：小节ID、同版教学源码与期望状态/输出：
- 有配音的制作任务：讲稿、音轨、分镜/时间轴版本：
- 运行环境任务：镜像/锁文件版本、源码挂载、端口与输出目录：
- 文档任务：受影响文档、来源、覆盖关系与需保留内容：

允许修改的范围：具体目录/文件
其他成员正在修改的范围：
保护范围：每课细纲、导入原件、他人已有修改；额外保护项：
依赖：哪些任务/输入到位后才能制作？
缺少输入时可先完成的工作：

交付物：
- 共用：实际修改、交付位置、验证记录与剩余限制；PR按任务要求
- Canvas：场景源码、可播放片段、关键状态与复现方法
- IDE：实际保存源码、stdout/退出码、真实录像与复现方法
- DevOps/集成：环境/接口修改、版本清单与实际复现证据
- 文档：可审查diff、来源/优先级核对、链接与一致性检查

验收（按本任务选择，其他标不适用）：
- [ ] 共用：范围内产物存在；输入版本、实际检查和限制可追溯
- [ ] Canvas/IDE：固定输入下教学代码与画面状态正确
- [ ] 制作：实际运行所需渲染/录制链，视频呈现约定结果
- [ ] 视频：完整解码、媒体参数符合任务、指定成员连续审片
- [ ] IDE：真实UI输入、保存与运行，磁盘源码/stdout/退出码正确
- [ ] DevOps/集成：约定环境从干净目录复现；跨机要求明确写由哪台机器执行
- [ ] 文档：角色、优先级、链接一致，受保护内容保留

技术检查、真人审片、跨机复现与合并分别记录，不互相替代。
复现说明只把实际存在且执行过的命令标为已验证；
需要新建的命令/接口列为待实现交付，完成后记录实际执行结果。

进展入口：本组status.md与证据地址；非制作任务记录其实际状态
本次变更/阻碍：需要谁做什么，引用正文，不再复制完整进度
交付状态：制作/修改已交付、审查、项目验收、合入分别记录
完成条件：范围内交付、适用验收、约定复核及必要合入均完成。
```

## 给任意 AI 工具的执行提示

```text
完成下面的任务，以实际产物和验证结果交付。
先读取本仓库根 AGENTS.md、当前小节README、本组req/status及任务输入。
全课范围、协作方法与其他docs仅按本次需要查阅；
旧项目req/status、导入AGENTS和其他历史研究是来源资料。
当前范围按附件模块汇总510分钟；每课细纲暂时不改，等用到再处理。
制作任务按根AGENTS的当前里程碑入口读取本组req/status和共享输入；
缺少本组文档时由本组任务先创建，只写已有要求和真实状态。
项目负责人维护架构与共同接口，制作成员维护详细需求与实际进度。
项目技能统一保存在仓库根skills/，与docs平级；按任务显式读取
skills/<skill-name>/SKILL.md及必要辅助文件。禁止为项目技能向
.codex、.agents、.qoder、.lingma、.claude等隐藏目录写入、安装、复制或建立链接。
Codex、Qoder、Claude Desktop均适用；先核实会话能够读取工作副本，
不能读取时报告缺口，不把保存位置当成客户端自动发现。

这是我的本机 WSL + Docker，仓库路径为 <本机实际路径>。
任务号 <ID>，分支 <分支>，基准提交 <SHA>。
只修改任务正文约定的范围；先检查工作区已有改动与正在进行的任务。
若同机有并行任务，使用已分配的 worktree 和独立 Compose 环境。

按任务类型执行检查，文档任务无需启动容器或制作视频。
需要容器的任务先核对实际源码挂载、工作区、端口和输出位置；
现有启动器未实现的参数不能假定可用，个人SSH/代理不当团队前提。
制作期间固定输入版本；源码/语法检查不能替代视频验收。
IDE任务必须经过真实UI输入、保存和运行，记录实际退出码和输出。
记录实际命令、失败证据、输入版本、交付位置与已执行检查。

完成后给出diff、任务要求的实际产物、复现方法和
通过/失败/未执行/不适用列表。团队交接写可取得的地址及必要哈希。
更新本组req/status、本任务证据和相关说明；Issue/PR引用本组正文，
项目负责人查看两组正文并维护共同接口，不同步第三份status。
非制作任务按其约定位置更新。
明确授权的文档整理任务可直接更新共用文档，保留已有内容。
既有授权内的实现直接推进；共享接口变化在任务/PR中说明影响。
改变教学目标或用户明确工具约束须依据用户的新明确决定更新需求。
视频/代码任务不能仅交计划，未执行的检查不能写通过。

任务正文：
<粘贴Issue、仓库任务文件或用户明确授权聊天中的完整正文>
```

## PR 正文

```markdown
关联任务：<Issue链接、仓库任务文件或完整授权任务摘要>

问题与结果：具体触发场景、修改后行为。
变更范围：本任务完成的修改及必要接口变化。

验证：
- 实际执行的命令与环境版本：
- 实际源码/输出检查：
- 视频、关键帧、验证记录：
- 连续审片：审查人、日期、结果，或明确未执行
- 干净环境/第二台机器复现：结果，或明确未执行
- 文档任务：来源、优先级、链接和保护范围检查结果

按任务类型选择字段，未执行与不适用分别标记。
限制/阻碍：尚未验证的内容，以及需要谁做什么。
```
