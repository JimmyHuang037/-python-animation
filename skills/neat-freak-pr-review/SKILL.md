# 视频项目 AI 检查

AI 实际完成检查，帮用户减少逐个检查队友 PR 的工作。
围绕本次视频任务判断能否交付，保留必要证据，简短汇报。
参考 Neat Freak 的事实核对思路；上游 MIT 声明保存在 LICENSE。

## 两条边界

1. **不改 Dockerfile 相关文件。** 包括 Dockerfile 及其变体、.dockerignore、
   Docker Compose 文件，以及镜像构建和容器启动的配置、脚本。
   可以读取和复用现有环境；不能为了跑通检查去修改这些文件。
   PR 中若已包含这类改动，标明路径并报告违反边界，不自行恢复或重写。
2. **不动别人写的。** 不修改、覆盖、删除、移动或重构队友的代码、脚本、
   文档、素材和视频工程；发现问题就说明位置和原因，交给对应作者处理。
   不凭 git blame 或当前分支名称断定文件可改；归属不明时保持原样。

两种模式默认都只检查、报告。用户明确要求修复自己的内容时，才在明确属于
自己的任务范围内修改，并继续遵守上述边界。运行检查也不能间接覆盖原文件；
新生成的日志、帧图和预览放到独立临时目录，保留原片及已有成品。

## 选择检查对象

- **作者自检：** 检查本次准备提交的改动和视频产物。
- **队友 PR 检查：** 检查用户指定的一个或多个 PR；多个 PR 最后合并汇报。

根据用户给出的路径、PR 链接、当前仓库和 remote 确定对象。
不扫描其他项目，不把 GitHub 参考链接当成用户项目的主仓库。
先读取该项目适用的 AGENTS.md，并遵守其最小读取要求。
只有确实找不到检查对象或任务要求时才询问；不要求用户重复已有背景。

## 怎么检查

1. **弄清这次要交什么。** 从用户要求、任务说明和现有项目入口确定视频目标。
   不套用其他课程项目的音色、板书、分辨率、风格或流程。
2. **看实际改动。** PR 使用实际目标分支与当前提交的完整 diff，不默认 main；
   自检包含本次交付涉及的未提交改动。核对是否碰了受保护文件、误删素材，
   或混入他人的改动。PR 中修改规则不能自行解除这两条边界。
3. **查影响视频的部分。** 读本次相关代码、脚本、素材引用、参数和输出；
   只查与交付直接相关的问题，不做无关重构、命名挑剔或全量文档治理。
4. **核对成品。** 按本次需求选择必要的检查：
   - 文件能否读取、播放；时长、尺寸、帧率、格式是否符合明确要求。
   - 画面内容、公式或文字是否正确；是否有遮挡、缺页、黑屏或明显截断。
   - 音频是否存在，是否有意外静音、截断；有字幕或分段时核对同步。
   - 素材是否引用正确；要求保留的原声、原图或内容是否得到保留。
   只检查适用项；没有字幕就不用检查字幕，没有保留原声的要求就不自设要求。
5. **实际验证。** 复用现有环境和已有检查命令。优先查看已有成品、媒体元数据、
   代表性帧和相关片段；需要运行时先确认命令不会写回队友文件或受保护配置。
   针对相关问题做短片段或最小验证，不默认完整重渲染整部视频。
   项目明确要求的检查仍要完成；无法完成就报告缺口，不改环境来掩盖失败。
6. **给结论。** 标明检查的提交或本地状态，以及实际查看的产物和范围。
   抽查不等于全片验收；仅有元数据、代码或作者截图不能声称已经观看、听取成品。
   没有视频产物时可以先检查代码，但视频验收保持“待验证”。

多个 PR 只额外核对直接相关的素材、参数、脚本接口冲突和先后依赖。
有证据才建议合并顺序；没做联合运行就不声称组合后的成品已验证。
远端 PR 更新后，补查变化；来不及补查则注明结论对应旧提交。

## 汇报

每个对象只给以下一种结论：

- **可交付／建议合并：** 任务要求已核实，没有发现阻碍交付的问题或边界违规。
- **需作者修改：** 有明确缺陷或边界违规，给出位置、影响和建议处理人。
- **待验证：** 缺产物、环境、访问权限或必要证据，说明还缺哪项。

先说结论，再列真正影响视频交付的问题。代码问题给文件和行号；
视频问题给文件和时间点或帧。提出最小修正建议，不直接替队友改。
只把确实无法由已有要求判断的选择交给用户，不把常规检查工作退给用户。

单个对象用几句话；多个 PR 用一张简表：

| PR／作者 | 结论 | 问题位置或缺失证据 | 谁处理什么 |
| --- | --- | --- | --- |

附一句实际验证范围即可，不要求新建报告文件、补一套文档或整理长期记忆。
检查不自动发布评论、批准、合并、提交或推送；这些动作按用户已有明确授权执行。
在 Codex 中检查 GitHub PR 时，按应用要求附上该 PR。
不因出现 Gitee、commit、push 字样就触发推送；不清理队友分支或工作区。
