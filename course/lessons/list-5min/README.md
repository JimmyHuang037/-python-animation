## 两条制作线的已明确要求

### 动画组：前2分30秒

- 延续当前 Motion Canvas 约束。先让 AI 查找 GitHub 成熟 skill，技能所在仓库 stars 超过1k；记录技能与仓库地址、查询日期、star数和技术适用性，区分技能仓库与框架仓库。
- 按根 AGENTS将选定技能完整下载到仓库根 `skills/<skill-name>/`，显式读取其 `SKILL.md`及所需辅助文件；禁止安装或复制到 `.codex/`、`.qoder/`、`.claude/` 等隐藏目录。随后生成一帧样例，交用户评价；满意后先生成30秒视频，再扩展到2分30秒。
- 样例不满意时，按用户给定路径使用 AI 的 image 功能生成图片供评价，或者搜索优秀网站范例，再生成视频。记录采用路径和反馈；外部技能与图片参考不自动改变用户规定的制作引擎。
- 具体分镜、场景分工、声音与时间轴由动画组写入自己的 `requirements.md`；样例、反馈、30秒片段和150秒片段的实际进度写入 `status.md`。旧宣传片不算本里程碑的30秒预览。

### Python 演示组：后2分30秒

- 在真实 Python 环境由 AI 自动准备代码、输入、保存、运行、修改和录屏；明确代理自动输入，并核对保存源码、真实输出和退出码。
- **必备：模拟机械键盘的打字声音。**声音与实际输入事件同步，不能把声音效果当作真实执行证据。
- **Premium 可选：**重点部分红圈勾画、补充 cue 使用注释气泡；未做可选项不因此判定必备交付失败。
- 教学代码、演示顺序、自动化与声音方案由王旭辉写入自己的 `requirements.md`；实际录制、运行与验证证据写入 `status.md`。不能把现有10秒环境预览当作150秒实操验收。

两组先在各自需求文档中引用同一份输入，项目负责人协调以下接口；本文件不代定具体代码、音色、分镜或像素参数。

## 给成员及其 AI 的读取顺序

1. 读取仓库根 `AGENTS.md`、本 README；不要求先读旧项目 req/status或全部 docs。调整全课范围时再读[课程 README](../../README.md)。
2. 按制作线读取本组 `requirements.md`、`status.md`；文件未建立时，由本组执行者先创建，写入已有用户要求、待补输入及真实状态。
3. 涉及衔接时读取另一组需求和共享输入；修改仅在当前任务约定的范围内。
4. 每次有实际进展更新本组 status，需求变更更新本组 requirements并记录来源。Issue/PR关联这些正文和证据，不再复制一份独立需求或完整进度。

客户端自动读取规则的行为需按实际工具核实。未确认自动加载时，将“先读取仓库根 AGENTS.md，再按其指引读取本组文档”放在客户端项目规则或任务开头。AI 接续时报告当前制作线、所读文档和输入版本，以便成员检查它使用的上下文。
